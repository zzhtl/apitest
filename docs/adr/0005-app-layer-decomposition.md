# ADR-0005：桌面层分层与每标签会话

## 状态

已接受。

## 背景

ADR-0001 声明应用层按「工作台外壳、状态、服务和功能视图」拆分，但实现始终是单个 `app.rs`（10,839 行），四类职责混在一起。同时，响应、编辑器分页、取消令牌和运行历史写入器都是应用上的单字段，导致多标签共用一份响应，切换标签会取消正在进行的请求。

## 决策

1. `apitest-app` 按 `state/`、`services/`、`ui/`、`theme/` 拆分，`app.rs` 只保留结构体定义与 eframe 装配。绘制函数通过 `UiExt::palette()` 取色，不再逐层传递 `Palette`。
2. 每个打开的文档拥有 `DocumentSession`，持有响应、分页选择、WebSocket 草稿、取消令牌和该次运行的历史记录。运行编号全局递增，事件按编号回查所属会话。
3. 断言与提取器求值移出 `ScenarioRunner`，成为 `apitest-runtime::verification` 的公开函数，场景执行与单次发送调用同一实现。

## 取舍

分层带来一次约 9,100 行的搬运改动，代价是一次性的巨大 diff；换来的是后续每个功能都落在 300–500 行的模块里。每标签会话让多个请求可以同时在飞，因此运行历史必须随会话走，否则并发运行会把两次响应写进同一条记录。求值层公开后，`apitest-runtime` 的公开 API 变大，但避免了两套语义不一致的断言实现。
